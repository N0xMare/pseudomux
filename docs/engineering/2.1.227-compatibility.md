# Claude Code 2.1.227: what a patch step actually moved

**Verdict: nothing this session could A/B for free moved, and it A/B'd everything it could.** Every
instrument below was run against `2.1.226` and `2.1.227` side by side on one host within one hour,
and **not one of them disagreed**: the launch bundle parses identically, the effort vocabulary is the
same array, the composer geometry and the `/clear` menu are cell-for-cell the same, the rotated
preamble is the same five rows and the same byte count, and `--strict-mcp-config` suppresses the same
outbound call.

**What that covers, counted rather than implied.** Of the 44 version-keyed sites §2 derives, this
session's A/B answers **16**. Another **24** — the composer group — were measured at 2.1.227 by the
criterion-1 work, at 2.1.227 only and not as an A/B against 2.1.226. **Four** were not re-measured at
all, and §9 names each. "Every version-keyed instrument" would have been the easier sentence and the
false one.

**Cost: 0 ledger ordinals; 6 real Claude turns, all through `pmux ask`, which reserves none.** Five
belong to the promotion run and are on its receipt; the sixth is §8's loop-closes proof and is
disclosed there because nothing counts it. The ledger is byte-identical before and after —
`439e48533a77679d15bcc24a5a555366dcf426131cc8a0ae1e2c105afb167153`, 1 200 199 bytes.

**This document is the answer to a product question, not only to a promotion.** The open question was
*how much calibration moves per release*. On this release, across the 40 of 44 sites something
re-measured, the answer is **none of it**. One data point is not a policy; §9 says what it does and
does not support.

**The single largest caveat, stated first.** A patch step is the easy case. Everything below is
`2.1.226 → 2.1.227` on macos/aarch64, one host, one account, a 24×80 pane and a 24×120 one. Nothing
here is a minor step, so trigger 5 — *a major or minor version change* — remains what it has always
been: a conservative policy default with no measurement behind it. And **17 of the 44 version-keyed
sites still name 2.1.220** (§2); the ones this session re-measured were re-measured at 2.1.227, not
re-grounded at the version their comment names.

## 1. Method

| instrument | what it can answer | cost |
| --- | --- | --- |
| `claude --help` on both binaries, diffed byte for byte | which options exist | 0 |
| **Non-executing flag probe** — `claude <FLAG> [value] --pmux-probe-sentinel doctor` — over a flag set DERIVED from the two files that build a Claude argv | whether every flag pmux can emit is parsed | 0 |
| `strings` over both Mach-O bundles | the effort array, the alias table, the warning template | 0 |
| **`pmux start --cell minified`** through the shipped release binaries | the whole bundle, the private root, the composer-geometry gate | 0 |
| **`ps -Eww` on the live child** | the argv and environment pmux really emits | 0 |
| **24×80 PTY replay of that captured argv + `pyte`** | the composer anchors, the `/clear` menu colours, the rotated preamble | 0 |
| `--debug-file` startup log, `--strict-mcp-config` removed and restored | the outbound connector fetch | 0 |
| `measure_transcript_drain.py --version 2.1.227` over the operator corpus | the free drain reading | 0 |
| **`promote_claude_version.py`** | the nine ordered checks, the drain over the daemon's own mirror | **5 turns** |

### 1.1 Every set under test is derived, and one derivation was wrong

The flag set is every `"-…"` string literal in `crates/service/src/claude_launch.rs` and
`crates/service/src/sensitive_launch.rs` outside their `#[cfg(test)] mod tests` tails — **25
spellings** — plus the `--effort` and `--permission-mode` vocabularies read out of `effort_name` and
`permission_mode_argv`. Nothing here is typed out, so a flag pmux starts emitting is probed without
anyone remembering.

The first version of the site scan in §2 split "production" from "test" at the **first**
`#[cfg(test)]` in each file. `claude_launch.rs` gates a production constant on `#[cfg(test)]` a
thousand lines above its test module, so that rule silently reclassified the `--effort` vocabulary —
one of the four sites `docs/version-drift.md` §3.6 names by hand — as a test, and the scan reported
31 sites instead of 44. The boundary is now the `#[cfg(test)]` that introduces `mod tests`. A
derivation is only worth more than a literal when its predicate is the thing it claims.

### 1.2 Two exclusions, both checked

`--bg` and `--background` are not probed. They do not parse the probe at all: they background an
agent and defer argv parsing to the child, which is `docs/2.1.226-compatibility.md` §7.1's
disclosure — and this harness reproduced that disclosure before excluding them (§10.1). The
exclusion is not trusted, it is checked: each name must be in `FORBIDDEN_DRIVER_FLAGS`, read out of
the Rust, so the day pmux starts emitting one the probe refuses instead of skipping a flag that
would then be load-bearing. The rest of `FORBIDDEN_DRIVER_FLAGS` **is** probed — `--session-id` is
on that list *and* in the minified bundle, because the list is about what a caller may add.

The probe's reply is matched for the flag as a **quoted token**, not as a substring. `-p` is a
substring of `--pmux-probe-sentinel`, so a substring test reads every accepted short flag as
rejected; the first run of this harness reported exactly that, and it is the house bug class in a
one-line predicate.

## 3. The launch surface

### 3.1 `claude --help` is byte-identical

`diff` over the two option tables returns **no differences at all**, and both publish **73** options.
That is a stronger result than 2.1.226's, which gained three options over 2.1.223 and lost none.

### 3.2 66 flag probes, zero disagreements

33 probes per version: the 25 derived spellings less the two of §1.2 and less `--effort` and
`--permission-mode`, whose vocabularies are probed value by value instead — 21 — plus five
`--effort` values, six `--permission-mode` values and the negative control.

| | 2.1.226 | 2.1.227 |
| --- | --- | --- |
| derived spellings ACCEPTED | 21 of 21 | 21 of 21 |
| `--effort low\|medium\|high\|xhigh\|max` | ACCEPTED ×5 | ACCEPTED ×5 |
| `--permission-mode default\|acceptEdits\|plan\|auto\|bypassPermissions\|dontAsk` | ACCEPTED ×6 | ACCEPTED ×6 |
| *control* `--definitely-not-a-flag` | REJECTED | REJECTED |
| **spellings whose result differs between the two** | **0** | |

`--permission-mode default` still deserves its note: `default` is not in either version's help and
both parsers accept it, so the choice-list tightening that would break Path A has still not happened.

### 3.3 The effort vocabulary is the same array in both bundles

`strings` on both binaries yields `["low","medium","high","xhigh","max"]`, `{med:"medium"}` and
`{ultracode:"xhigh"}` beside it, and the same unknown-value warning template — *"ignoring it and
using the default effort. Valid values: "* — rendered from that same array. The only difference
between the two bundles at this site is the minified variable name holding the array. So
`CLAUDE_ACCEPTED_EFFORT_SPELLINGS` is correct at 2.1.227, `ultracode` is still normalized to
`xhigh`, and `docs/2.1.226-compatibility.md` §6.4 remains open for the same reason it was.

## 4. The bundle end to end, and the argv is captured rather than composed

`pmuxd` was booted with an operator-supplied **probe** cell for each version — a probe input, not a
promotion; `PROMOTED_PROFILES` was untouched at the time — and `pmux start --cell minified` reached
`state: ready` at both, with `tested: true` and `transcript_drain_ms: 1000`, in **1072 ms** at
2.1.226 and **1261 ms** at 2.1.227.

`state: ready` is returned only after `classify_terminal_snapshot` returns `Ready` on a snapshot that
held still — i.e. after pmux's own emulator found an empty active composer inside
`MAX_RENDERED_ROWS_BELOW_ACTIVE_CURSOR`. One command therefore proves argv acceptance, the private
root, the 24×80 pane and the composer-geometry gate, at 2.1.227.

**The credential pin is a separate reading, and it is direct.** `ready` does not establish it — a
composer renders either way. The PTY replay of §5 does: the 2.1.227 cell's own welcome box, inside a
private root pmux seeded, reads *"Sonnet 5 with low effort · Claude Max · <account>'s
Organization"*. A cell that had not resolved the operator's credential through
`sha256(config_dir)[0..8]` would be showing a login prompt instead.

The child's real command line, read out of `ps -Eww` while it was alive, is identical at both
versions modulo the session uuid and the temporary paths:

```
--session-id <uuid> --model sonnet --effort low --permission-mode dontAsk \
  --disallowedTools * --strict-mcp-config --system-prompt-file <path>
```

which is `MINIFIED_LAUNCH_FLAGS` in argv order, and **13** environment names, the same 13 at both.
Everything in §5, §6 and §7 replays *that* argv, so no result below is a claim about a command line
this document invented.

## 6. `/clear`

### 6.1 The free path to it is the PTY, not `pmux clear`

`pmux clear` refuses before a turn has run — *"no validated main transcript exists yet"* — because
the fence is the validated main transcript and a session that has answered nothing has none. So the
only 0-ordinal instrument for the rotated preamble is a raw PTY, and `pmux clear`'s own predicates
are exercised instead by the pool recycling inside the paid run (§7).

`/clear` also has to be typed one character at a time. A single write of the six bytes is accepted by
the pty and is not rendered as a slash command; the composer still showed its placeholder three
seconds later.

### 6.2 The menu marks its selection with a foreground colour and nothing else

Per-cell foreground colours from the rendered grid, over the rows that begin with `/`:

| row | text | 2.1.226 | 2.1.227 |
| --- | --- | --- | --- |
| 16 | `/clear  Start a new session with empty context; …` | **`#afd7ff`** | **`#afd7ff`** |
| 18 | `/code-review  3 free /ultrareview · …` | **`#949494`** | **`#949494`** |

`#afd7ff` is xterm **153** and `#949494` is xterm **246** — exactly the pair recorded for 2.1.220 and
re-measured at 2.1.226, so `crates/rmux/src/backend.rs`'s claim that the menu marks its selected row
with *"a foreground colour change"* holds at 2.1.227.

*Safety.* Enter was pressed only after the minority-foreground row's text was asserted to begin with
`/clear`, and the composer row is excluded from that vote — it renders in the same colour, which is
how §3.3 of the 2.1.226 receipt says its first guard mis-fired. This harness's first guard failed the
same way and pressed ESC, which is the fail-safe direction working.

### 6.3 The rotated preamble

Pressing Enter rotates the transcript. The rotated file, at **both** versions:

| row | type | subtype |
| --- | --- | --- |
| 0 | `mode` | — |
| 1 | `file-history-snapshot` | — |
| 2 | `user` | — |
| 3 | `user` | — |
| 4 | `system` | `local_command` |

**5 rows, 2 of them `user`, row 0 `mode`, at both versions.** `ROTATION_ANCHOR_ROW_TYPE` is row 0;
`MAX_ASSERT_EMPTY_ROWS = 16` admits 5; `MAX_ASSERT_EMPTY_USER_ROWS = 2` is met exactly. The rows
carry `"version":"2.1.226"` and `"version":"2.1.227"` respectively and `"entrypoint":"cli"`.

**The byte size is 1935 at both** — not the 1899 the 2.1.226 receipt measured. The A/B settles what
matters: **it is not a version difference**, because the two versions agree with each other under one
harness. What it *is* was not measured. These rows embed the session's own working directory and this
harness's is a different length from the earlier one's, which is the obvious candidate and is an
inference, not a reading; nothing here varied the cwd to check it.

It is worth recording because `driver_io.rs` still states *"the 5-row preamble is 1051-1890 bytes"*:
that range was 9 bytes short in the 2.1.226 receipt and is **45 bytes short** here. Nothing is at
risk — the predicate is `MAX_ASSERT_EMPTY_BYTES = 64 * 1024`, and the stated range decides nothing —
and this is `docs/2.1.226-compatibility.md` §6.5 still open, with a second measurement behind it.

## 7. The drain, and the two things that can measure it

`measure_transcript_drain.py --corpus ~/.claude-1/projects --version 2.1.227 --bound-ms 1000` exits
**5** — *nothing to check*. There is not one `"version":"2.1.227"` row in the operator's corpus, and
there was not one at 2.1.226 on the day it was promoted either. The free schema-drift detector is
vacuous at exactly the moment it is wanted, twice in a row now, which is `docs/version-drift.md`
§2.2 and §P3 reproducing rather than being predicted.

What answers it is the daemon's **own** evidence mirror, written by `Pool::destroy` during the paid
run and read by the same tool at the same bound:

| | 2.1.226 | 2.1.227 |
| --- | --- | --- |
| reachable post-answer arrivals | 5 | 5 |
| max | 223 ms | **52 ms** |
| median | — | 25 ms |
| pooled bound asserted against | 1000 ms | 1000 ms |
| **per-version fit, published and NOT shipped** | 500 ms | **250 ms** |

The fit is the number to read. **250 ms is below `POST_MARKER_CATCH_WINDOW_FLOOR_MS = 438`**, so a
promotion that fitted its own version instead of reading the pooled bound would have shipped a drain
that truncates answers. Three runs at 2.1.226 fitted 250, 500 and 500; this one fits 250. That is
`docs/version-drift.md` §3.2 landing under the floor on a fourth version's numbers.

`--strict-mcp-config` reproduces too, with the flag as the one variable moved and the child's own
`--debug-file` as the instrument:

| arm | MCP lines | `MCP configs resolved in` | fetches the account connector list |
| --- | --- | --- | --- |
| 2.1.226, as shipped | 3 | 1 ms | no |
| 2.1.226, flag removed | 6 | 5 ms | **yes** |
| 2.1.227, as shipped | 3 | 0 ms | no |
| 2.1.227, flag removed | 6 | 5 ms | **yes** |

The flag still removes an outbound HTTPS call to `api.anthropic.com/v1/mcp_servers` and a 294-entry
registry load, at 2.1.227, and costs the cell nothing. The "3" is this harness's line filter, which
also counts `mcp runtime arm: v1`; the constant's own table says 2 and both versions agree with each
other under either filter.

## 9. What this establishes about the product question, and what it does not

**It establishes that a patch step can cost nothing.** Sixteen of the 44 version-keyed sites were
answered by an instrument run at BOTH versions, and none disagreed; 24 more were measured at 2.1.227
alone by the criterion-1 work. On the strength of that, the standing instruction — support the latest
Claude Code, tolerate patch drift, force re-promotion on a minor — is consistent with what this patch
step did to *this* codebase.

**An A/B and a single-version measurement are not the same evidence**, which is why they are counted
separately. A property measured only at 2.1.227 is known to hold there; it says nothing about whether
the step moved it, because there is nothing to compare against. The 16 are the ones that answer the
question this document is about.

**It does not establish that patch steps are safe in general.** It is one step, on one host, and the
sample of releases where nothing moved is now one. `docs/2.1.226-compatibility.md` found four
recorded facts wrong at 2.1.226 that had *already* been wrong at 2.1.223 — drift accumulates
silently between the versions anyone bothers to measure, and a step that moves nothing is not
evidence that the previous ones moved nothing.

**It does not establish anything about a minor step.** Trigger 5 is a policy default, not a
measurement, and nothing here tested it.

Also not established:

* **The tool surface is not proven empty by these free probes.** The paid run is what proves it, and
  it proves it the strong way: `sidechain` and both cache counters zero on all five results.
* **macOS/aarch64 only**, one account. Two pane sizes and no others: 24×80 for every PTY replay, and
  the 24×120 `stateless.rs::POOL_TERMINAL` for every turn the promotion run drove.
* **Four of the 44 sites were not re-measured**, and §2 marks each: residue per root, the +39 ms
  rotation latency, `XDG_CONFIG_HOME`, and the model/effort pairs the CLI absorbs. The last needs
  five turns.
* **The composer's own trailing-character behaviour was not re-run here.** It was measured at 2.1.227
  by the criterion-1 work, which is why §2's largest group says so rather than claiming this session
  did it.

## 10. Disclosures

### 10.1 Four background agents were started, and produced no model output

The first version of the flag probe probed `--bg` and `--background`. Both consumed the rest of the
command line as a prompt and backgrounded an agent — twice per version, four in total. Every one is
accounted for, from its own `~/.claude-1/jobs/<id>/state.json`:

* `"state": "failed"`, `"detail": "exit 1 before init — error: unknown option '--pmux-probe-sentinel'"`
* `"output": null`, `"model": null`, `"usage": null`
* lifetimes 0.1 s to 1.9 s (`createdAt` → `firstTerminalAt`)

No model output was produced, the ledger is unchanged, and the four job directories were removed.
This is `docs/2.1.226-compatibility.md` §7.1 happening a second time, in a harness written after
reading it, which is why §1.2's exclusion is a checked precondition rather than a note.

### 10.2 Every launch makes a startup quota check

Each launch logs an `/v1/messages` request with `source=quota_check` — re-read here from a 2.1.227
child's own `--debug-file`, one line, `[API REQUEST] /v1/messages x-client-request-id=… source=quota_check`.
It is the CLI's own startup behaviour, present on every pmux launch the ledger has ever recorded, and
it generates no assistant turn. Disclosed because a probe that "sends nothing" still causes it, and
re-read rather than quoted because a disclosure inherited without measurement is the thing §1.1 is
about.

## 11. Reproducing this

```sh
export PYTHONDONTWRITEBYTECODE=1
claude --version                                    # 2.1.227 (Claude Code)
diff <(.../2.1.226 --help) <(.../2.1.227 --help)    # empty

# flag probe: executes nothing, ever
.../2.1.227 --system-prompt-file /tmp/x.txt --pmux-probe-sentinel doctor
#   -> error: unknown option '--pmux-probe-sentinel'      (flag accepted)
.../2.1.227 --definitely-not-a-flag        --pmux-probe-sentinel doctor
#   -> error: unknown option '--definitely-not-a-flag'    (flag rejected)

# free corpus: exit 5, nothing to check
python3 tools/promotion/measure_transcript_drain.py \
  --corpus ~/.claude-1/projects --version 2.1.227 --bound-ms 1000

# the paid part, and the only part that writes a receipt
python3 tools/promotion/promote_claude_version.py \
  --release-dir target/release --claude ~/.local/share/claude/versions/2.1.227 \
  --output evidence/promotion-2.1.227-macos-aarch64.json
```

The site scan, the A/B flag probe, the `pmux start` A/B, the 24×80 PTY replay and the
`--strict-mcp-config` arm were scratch harnesses under `/tmp`, removed after the run. They are
described in enough detail above to rebuild: `git ls-files 'crates/*/src/**.rs'` with a ±6-line
window and the `mod tests` boundary of §1.1; the derived flag set of §1.1 with the two exclusions of
§1.2; `pmux start --cell minified` under `Sandbox`/`Daemon` from
`tools/promotion/measure_turn_latency.py`; `ps -Eww` for the child's argv and environment, replayed
through `pty.fork` at 24×80 into a `pyte` screen after `chdir` to the session's own `--cwd`; and the
same argv with `--strict-mcp-config` removed and `--debug-file` added.
