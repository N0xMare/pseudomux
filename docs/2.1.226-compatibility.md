### 1.1 The flag probe, and why it executes nothing

`claude --version` short-circuits *before* commander validates options, so `claude --bogus --version`
prints `2.1.226` and proves nothing. `claude <FLAG> doctor` does discriminate — but when `<FLAG>` is
variadic or optional-valued it swallows `doctor` as a *prompt*, which is how the first version of this
probe started two background agents (§7.1).

The probe used below appends a sentinel that is guaranteed unknown:

```
claude <FLAG> [value] --pmux-probe-sentinel doctor
```

Commander reports the **first** unknown option and exits 1 without running anything — verified:
`claude --aaa-not-a-flag --bbb-not-a-flag doctor` names `--aaa-not-a-flag`. So the reply is
`unknown option '--pmux-probe-sentinel'` when `<FLAG>` is accepted and `unknown option '<FLAG>'`
when it is not, and no prompt, subcommand or session ever runs.

### 1.2 The flag set is derived, not typed out

The set under test is extracted from the two files that build a Claude argv — every `"-…"` string
literal in `crates/service/src/claude_launch.rs` and `crates/service/src/sensitive_launch.rs`,
outside their `#[cfg(test)] mod tests` tails. That yields **24 spellings**: the 13 pmux constructs
(`--session-id`, `--resume`, `--model`, `--effort`, `--permission-mode`,
`--dangerously-skip-permissions`, `--allowedTools`, `--disallowedTools`, `--settings`,
`--mcp-config`, `--plugin-dir`, `--system-prompt-file`, `--append-system-prompt-file`), the
two-flag extra-arg allowlist (`--debug`, `--verbose`) and the `FORBIDDEN_DRIVER_FLAGS` it refuses.

Two of them — `--system-prompt-file` and `--append-system-prompt-file` — **are not in `claude --help`
at either version.** They are hidden options, and `--system-prompt-file` is load-bearing for Path B
(`crates/service/src/sensitive_launch.rs:56`). A help-text diff would have said nothing about them.
The live probe is what covers them.

export PYTHONDONTWRITEBYTECODE=1
